## 새 동작의 확인 내용

- 건물명 수정은 같은 사무소 대표·관리자만 가능하고, 오래된 수정 요청은 거부한다. 연결된 매물의 표시명을 원자적으로 바꾸며 가격과 ID는 유지한다. 보기 삭제 후 신규 선택과 연결은 막되 기존 매물 수정·계약 조회는 계속 작동한다. 직접 REST의 삭제 상태 생성도 막는다.
- 기존 법률 검토 값은 그대로 보존하고 새 실무 체크·메모를 별도로 저장한다. 같은 사무소라도 다른 담당 직원은 수정할 수 없다. 익명·다른 사무소·오래된 버전·알 수 없는 키·불리언이 아닌 값은 차단한다.
- 삭제한 직원에게 과거 업무를 25개 만든 후 기본 집계에서 제거되는지 확인했다. SQL의 상위 20건 제한 전에 제외돼 현재 직원 업무가 밀리지 않는다. 명시적 담당자 선택에서는 옛 업무가 여전히 조회되고 원본 25개는 보존된다. 만기 업무 우선순위에도 동일하게 적용된다.
- 같은 계약의 잔금일과 만기일을 각각 조회하고, 월 경계·다른 사무소 조회 차단을 확인했다. PC와 390px 모바일에서 통합 캘린더의 잔금/만기 문구와 상세 링크를 확인했다.
- 계약 목록에서 다른 담당자의 항목은 선택을 막고 현재 페이지의 삭제 가능 계약만 전체 선택한다. 일부 계약을 다른 화면에서 수정한 상황에서 1건 성공·1건 실패를 구별하며, 서버 목록이 갱신될 때까지 재시도를 잠깐 막고 새 버전으로 실패 건만 재시도할 수 있다. 계약 원본 3개를 보존하면서 삭제할 2개만 숨기는 실제 브라우저 조작을 확인했다.
- 만기 화면의 실무 체크 저장, 역할·전화번호·금액 표시, 접는 추가 확인/이력, 실제 상담 저장·한국 시간·퇴거 확인·재임대 검토·갱신·업무 완료를 검증했다. 테스트도 접는 영역을 펼치고 응답 저장이 끝난 뒤 다음 동작을 하도록 변경했다.
- 매물 고객 수정 버튼은 요약 첫 줄 오른쪽으로 이동했으며 버튼의 세로 위치를 브라우저 좌표로 확인했다.
- 가상 자료의 정리는 생성한 UUID만 대상으로 했다. 보관 자료를 복구하거나 불변 이력을 지우는 앱 기능은 추가하지 않았다.
