# 017 — 선택 삭제, 보기 관리와 실무 업무 화면

## 구현

- 계약 목록에서 개별 선택·현재 페이지 전체 선택·선택 삭제를 제공한다. 담당자 또는 대표·관리자가 삭제할 수 있는 항목만 선택한다. 기존 DELETE API와 각 계약 버전을 그대로 사용해 권한·동시 수정을 검사한다. 한 건이 실패해도 성공한 계약은 유지하고 결과를 각각 알려 준다. 결과 새로고침이 끝나야 다시 삭제할 수 있다. 소프트 삭제 정책과 당사자·서류·수납·갱신 이력 보존은 016과 같다.
- 매물 관련 고객의 수정 버튼을 고객 요약 첫 줄 오른쪽으로 이동했다. 기본 목록에 수정 버튼만을 위한 아랫줄을 추가하지 않는다.
- 매물 목록과 등록 화면의 `건물·단지 보기 관리`에서 건물 목록을 열고 이름·주소·총층수 수정, 보기 삭제를 할 수 있다. 같은 사무소 대표·관리자만 변경한다. 이름 수정은 연결된 삭제되지 않은 매물의 표시 이름도 같은 트랜잭션에서 갱신하고 버전을 올려 오래된 수정 화면의 덮어쓰기를 방지한다. 가격·담당자·계약 ID는 유지한다.
- 보기 삭제는 deleted_at을 기록해 새 등록·일반 보기 목록에서 숨긴다. 연결된 매물·계약·주소 이력은 삭제하지 않는다. 신규 매물의 삭제된 보기 연결은 DB에서 막지만, 이미 연결된 매물은 조회·수정·계약 일정 자동화가 계속 작동한다. 삭제한 보기의 이름을 다른 보기에 즉시 재사용하거나 UI에서 복구하는 기능은 이번 작업에 추가하지 않았다.
- 기본 `미처리 업무 우선순위`와 담당자별 미처리 건수는 active=true이고 deleted_at이 없는 직원의 업무만 집계한다. SQL에서 상위 20개를 자르기 **전에** 필터링해 삭제한 직원 업무가 현재 직원 업무를 밀어내지 않는다. 삭제한 직원의 자료는 보존하며 담당자를 명시적으로 선택하면 인계용 업무를 다시 볼 수 있다. 전체 매물·계약 수치와 만기 원본 기록을 삭제하거나 실제 상태를 변경하지 않는다.
- 홈 캘린더는 잔금일과 만기일을 함께 표시한다. 잔금은 체결·진행·완료 계약의 closing_date, 만기는 체결·진행 중 임대차의 lease_end_date를 사용한다. 초안·취소·삭제 계약은 제외한다. 같은 계약이라도 두 일정이 각각 표시되고, 같은 날이면 잔금·만기 두 항목이 된다. 각각 날짜·색상·문구로 구분하고 계약 상세로 연결한다. 담당자·월 필터와 사무소 RLS가 적용된다.

## 실무 중심 만기확인

기본 화면에 만기일·잔금일·보증금·월세, 임대인/임차인 이름·연락처, 연장·재계약·이전 상담 바로가기를 둔다. 같은 사무소 인증 직원만 고객 연락처를 읽을 수 있고 고객 접근기록을 남긴다.

실무 체크는 임대인 연락, 임차인 연락, 연장/이전 의향, 퇴거/보증금 일정, 새 임차인 모집 계획과 업무 메모다. 새 work_checks/work_note 필드를 사용한다. 이전 법률 검토용 review_checks/review_note를 다른 의미로 재사용하지 않으므로 과거 확인 기록을 보존한다. 기존 업무 이력·버전·RLS가 그대로 적용되고 새 체크에도 권한과 동시 수정 검사를 한다.

연락 등록은 기본으로 열고, 연장·퇴거·정산 현황, 퇴거 후 재임대, 연락 이력, 만기 업무·갱신·이전 이력은 필요한 때 펼친다. 기존 추가 확인 사항은 마지막 접는 영역에 유지한다. UI를 간소화했지만 상담·실제 퇴거·보증금 정산·매물 재거래 검토·계약 갱신 기능은 제거하지 않는다. 체크 완료만으로 법적 효력이나 실제 계약 종료를 판정하지 않는다.

## DB 및 적용

마이그레이션 `202610160017_practical_workdesk.sql`은 property_buildings.deleted_at, contract_followups.work_checks/work_note를 추가하고 건물 수정 권한·보호 트리거와 두 대시보드 집계 함수를 확장한다. 공개 테이블은 기존 26개이며 모두 RLS를 유지한다. 새 집계와 건물명 갱신은 security invoker로 실행한다.

기존 환경 설정과 Docker 볼륨을 보존한 최신 코드에서 실행한다.

```bash
bash scripts/start-local.sh
npm run dev
```

017 추가 업데이트가 필요하다. DB reset을 하지 않는다. 실제 배포·유료 서비스·외부 알림 전송은 추가하지 않았다.
