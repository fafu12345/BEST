# 5단계: 계약 만기·갱신·이전 고객관리

## 실행과 화면

최신 코드를 받은 뒤 기존 `.env.local`, `local/.env`와 Docker 볼륨을 유지합니다.

```bash
npm ci
bash scripts/start-local.sh
npm run dev
```

011 추가 마이그레이션을 적용해야 새 화면이 작동합니다. Docker 데이터 초기화는 필요하지 않습니다.
ZIP 사용자는 새 폴더에 최신 ZIP을 풀고 기존 설정 파일 두 개를 같은 위치로 복사합니다.

- **만기관리** (`/dashboard/expiration`): 활성 임대차 만기 임박·경과 미처리·직원별 계약과 업무 일정.
- **계약 상세 → 만기·연락·퇴거 관리**: 연락 결과·통지/협의·다음 연락·예정/실제 퇴거·보증금 정산·모집 여부.
- **갱신·재계약 생성**: 원계약 당사자와 금액을 참고값으로 불러와 새 기간·금액을 확인하고 저장.
- **이전 희망 등록 / 이전 고객관리**: 기존 계약 당사자의 희망조건, 담당자, 다음 연락과 수동 연결 매물 관리.

PC는 계약/이전 목록을 표로, 모바일은 카드로 표시합니다. 업무와 연락 이력은 20건씩 페이지를 나눕니다.
계약과 업무의 목록 범위는 각각 계약 종료일, 업무 알림일을 기준으로 합니다. 한국 날짜·시간을 사용합니다.
별도 SMS·이메일·푸시 전송은 없습니다. 화면의 업무 목록으로 확인합니다.

## DB와 권한

`202610150011_expiration_management.sql`은 기존 contracts와 contract_events를 유지하고 다음 4개 테이블을 추가합니다.

| 테이블 | 용도 / 핵심 필드 |
| --- | --- |
| contract_followups | 계약당 한 행. result, notice_status, resolution_status, next_contact_at, 예정·실제 퇴거일, 정산·모집·재임대 검토 현황, 마지막 연락 요약, version |
| expiration_tasks | contract_id, assigned_staff_id, task_key, reminder_days, base_end_date, scheduled_date, status, completed_at, completion_note, relocation_case_id, version |
| contract_renewals | source_contract_id, renewed_contract_id, renewal_type, renewal_number, old_terms/new_terms, processed_at |
| relocation_cases | customer_id, contract_id, 사유·희망 지역·면적·예산·이전 시점, status, selected_property_id, assigned_staff_id, next_contact_at, notes, version |

업무 테이블은 총 21개이며 모두 RLS를 적용합니다. 일반 업무 읽기·쓰기와 두 공개 업무 RPC는 사용자 세션/SECURITY INVOKER로 실행합니다.
계약 담당자(대표·관리자 포함)만 계약별 연락/현황을 변경하고, 이전 건과 해당 후속 업무는 이전 담당자가 변경합니다.
대표·관리자만 이전 담당자를 변경할 수 있습니다. 계약 담당자 변경 시 해당 계약의 미완료 일반 업무와 현황 담당자를 동기화합니다.
완료 업무의 담당자·예정일·내용은 역사적 기록으로 유지합니다. 연락 기록자는 로그인한 직원으로 감사 이벤트에 기록합니다.

같은 사무소 직원만 조회합니다. 사무소 ID는 서버에서 결정하고 FK는 office_id를 포함합니다.
다른 사무소 계약·고객·매물 연결을 DB에서 차단합니다. 이전/연락 고객은 해당 계약 당사자여야 합니다.
테이블·컬럼 권한과 트리거는 신원·사무소·연결·담당자 조작을 제한합니다.
새 테이블에 인증 사용자의 하드 삭제 권한은 없으며 완료 업무와 갱신 이력은 변경하지 못합니다.

파생 업무/현황 생성과 감사 이벤트를 쓰는 비공개 트리거 함수만 좁은 SECURITY DEFINER 권한을 사용합니다.
외부에서 이 함수를 직접 실행할 수 없고, 인증·사무소 RLS를 거쳐 저장된 부모 행으로만 파생합니다.
일반 업무 경로에 service_role을 사용하지 않습니다.

## 업무 생성·재계산과 실패 재처리

예약 작업, 백그라운드 프로세스, cron이나 새 서버 키를 요구하지 않습니다.

1. 유형이 확인된 전세·월세 계약 저장 트랜잭션에서 계약별 현황을 준비합니다.
2. 체결/진행 중이고 종료일이 있으며 후속 처리가 열려 있으면 180·90·60·30일 업무를 생성합니다.
3. `(office_id, contract_id, task_key)` UNIQUE와 UPSERT로 동일 기준 업무 중복을 막습니다.
4. 직원이 알림일을 바꾸면 종료일과의 일수 차이로 저장합니다. 기간 변경 시 미완료 업무는 이 기준으로 재계산합니다.
5. 완료 업무는 당시 날짜/내용을 보존합니다. 취소/초안 전환·기간 삭제·후속 처리 완료 시 미완료 기준 업무를 취소합니다.
   다시 활성화하면 기존 미완료 기준 업무를 재사용하고 재계산합니다. 완료 업무를 새로 덮어쓰지 않습니다.
6. 연락 결과와 다음 연락일을 저장하면 이전 미완료 다음 연락 업무를 취소하고 새 업무를 만듭니다.
   처리 완료 후 다시 열 때도 다음 연락일이 있으면 후속 업무를 다시 만듭니다.
7. 이전 건의 연락일/상태 변경도 담당자별 후속 업무를 생성·취소합니다. 완료 이력은 유지합니다.
8. 예정/실제 퇴거일 기록은 재임대 검토 업무를 생성합니다. 실제 퇴거 확인 후 명시적으로 매물 상태를 검토·반영해야 합니다.

업무 생성 실패는 부모 저장과 함께 롤백하므로 계약만 저장되고 업무가 빠지는 부분 성공을 만들지 않습니다.
동일 요청을 다시 실행하면 UNIQUE/버전 검사로 중복과 덮어쓰기를 막습니다.
네트워크 오류로 성공 여부가 불명확하면 상세를 새로 조회한 뒤 재시도합니다. 버전 충돌(409)은 최신 내용을 읽고 다시 저장합니다.
DB 연결 장애는 복구 후 재시도합니다. 011 마이그레이션은 트랜잭션이고 실패한 파일은 로컬 적용 기록에 남기지 않으므로
원인 해결 후 `bash scripts/start-local.sh`로 재실행할 수 있습니다. 실패 시 첫 SQL 오류를 확인하고 DB 초기화는 하지 않습니다.
기존 계약의 작업 누락을 확인해야 할 경우 담당자가 계약을 다시 저장하면 동일 동기화가 실행됩니다.

오늘/기한 경과는 조회할 때 한국 날짜와 저장 날짜를 비교합니다. 날짜가 넘어갈 때 따로 업무를 새로 만들 필요가 없습니다.
켜둔 화면은 새로고침/조회하면 갱신됩니다. 예약 서버의 실행 실패나 큐 재처리 작업은 없습니다.

## 연락·갱신·이전·퇴거의 의미

연락 결과는 미확인, 계약 연장 희망, 다른 매물로 이전 희망, 퇴거 예정, 협의 중, 계약 종료입니다.
연락 시각·방법·상담 내용·당사자 이름 스냅샷·기록 담당·다음 연락을 불변 contract_events에 누적합니다.
계약별 마지막 요약을 수정해도 과거 연락 이벤트를 삭제하거나 덮어쓰지 않습니다.
현황 변경과 이전 희망조건 변경 역시 같은 계약의 감사 이벤트에 남습니다.

`same_terms`는 **별도 문서 없이 기존 조건 유지**를 직원이 확인해 기록하는 업무 구분입니다.
법률상 묵시적 갱신이나 갱신권 행사로 자동 판정하지 않습니다. 보증금·월세·관리비·당사자·계약 유형이 달라지면 이 구분으로 저장할 수 없습니다.
`written`은 **신규 계약서 작성** 구분이며 새 조건으로 계약을 생성합니다. 실제 서류는 기존 비공개 계약 서류 기능으로 첨부합니다.
새 임대차 기간, 처리일, 신규 계약 생성과 원계약 관계/조건 스냅샷 저장은 하나의 트랜잭션입니다.
갱신 차수는 원본 계약 연결을 따라 계산합니다. 조건 비교는 갱신 당시 스냅샷으로 표시합니다.
한 원계약의 처리된 갱신은 한 건이며 다음 갱신은 새 계약에서 진행합니다. 잘못 생성한 갱신의 재지정/취소 연결 해제는 이번 단계에 제공하지 않습니다.
기존 4단계의 previous_contract_id 연결은 유지하되 과거 갱신 유형/처리일을 추측하여 채우지 않습니다.

갱신은 원계약의 **후속 처리**를 완료하지만 원계약 상태·금액은 바꾸지 않습니다. 차기 만기는 새 계약에서 관리합니다.
계약 취소·종료는 기존 계약 수정에서 담당자가 명시적으로 처리합니다.
만기 경과, 고객의 종료 의향, 실제 퇴거, 보증금 정산, 재거래 가능 여부는 서로 독립적입니다.
법정 통지·갱신기간과 권리·효력은 담당자 확인 사항으로 표시합니다.

이전은 자동 매칭 없이 사유·희망 지역·면적(㎡)·예산(원)·가능 시점·진행 상태를 기록합니다.
화면에서는 예산을 만 원으로 입력하고 면적의 평 환산을 함께 봅니다. 인증된 수동 매물 검색으로 한 개의 검토 매물을 연결/해제합니다.
이전 상담 메모와 변경 내용은 원계약 이벤트에 남고 다음 연락 업무는 이전 담당자에게 배정됩니다.
원계약의 구조화된 연락 이력은 계약 담당자가 관리합니다.
