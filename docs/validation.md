테스트의 일반 업무 요청은 사용자 세션으로 수행합니다. service_role은 테스트 실행이 생성한 가상 행·파일 정리에만 사용합니다. 마지막 검사 후 기존 가상 직원 5명, 매물 3건을 유지했고 임시 파일·이력·추가 매물·건물 보기까지 모두 정리했습니다. 새 마이그레이션 검사 DB도 제거했습니다.

업그레이드 검사는 기존 전세금/월세·버전·확인일을 바꾸지 않고 건물 보기를 가져오는지 검사합니다. 담당자가 비활성인 기존 매물과 빈 건물명도 포함하며, 형식 변경 때문에 허위 가격 이력이 추가되지 않는지 확인합니다. 업무 트리거와 RLS가 활성 상태로 복구되는지도 검사합니다. 기존 API 요청에 새 필드가 빠져도 선택한 건물·상호·임대 금액이 지워지지 않는 호환성 검사를 포함합니다.

## 환경과 제한

공식 Supabase GoTrue v2.197.0, PostgREST v16.4, Storage v1.82.1, Kong 2.8.1과 PostgreSQL 17을 실행하는 경량 로컬 구성을 사용했습니다. Auth/Storage를 가짜 fixture로 대체하지 않았습니다. 전체 Supabase CLI DB 이미지는 1단계에서 디스크 제한으로 구동하지 못했으므로 CLI 전체 구성은 미검증입니다.

Playwright 기본 브라우저 CDN은 환경 네트워크 정책에 의해 403으로 차단되었습니다. 공식 Google 다운로드에서 TLS 검증을 유지해 받은 Chrome 155를 CHROME_EXECUTABLE_PATH로 지정하여 브라우저 검사를 완료했습니다. 패키지·TLS 검증을 비활성화하지 않았습니다.

삭제 행은 같은 사무소의 감사용 DB SELECT에 남습니다. 앱의 활성 목록·상세·중복 검색은 제외하며 첨부파일은 DB/Storage 정책으로 차단합니다. 복원·영구 삭제 UI, 고객 CRUD UI는 이번 단계 범위가 아닙니다. DB와 Storage의 동시 변경 정리 제한은 [매물관리 안내](property-management.md)를 참고하세요.

외부 메일·매물 연동, 실제 개인정보, 원격 DB 적용, 클라우드 배포 및 유료 서비스 생성은 수행하지 않았습니다.

### 대량 데이터와 성능

실제로 가상 매물 1,000개, 고객 500명, 계약 1,500건, 당사자 3,000건, 만기 업무 6,000건을 두 사무소에 만들었습니다. 계약 집계는 A 1,400건/B 100건의 추가분을 정확히 반영해 REST 1,000행 제한으로 누락되지 않았습니다. 시험 후 이 실행이 만든 매물·고객·계약 등만 제거했습니다. 삭제 행위의 감사 기록은 로컬 가상 이력에 남을 수 있습니다.

각 API를 10회 호출한 최종 측정의 p95는 통계 142ms, 알림 142ms, 대시보드 2,356ms, 계약 목록 125ms, 매물 목록 118ms, 고객 목록 122ms였습니다. 응답은 최대 약 29KB이고 목록 20건 제한을 확인했습니다. 로컬 예산 p95<5초를 통과했습니다. [performance-results.json](performance-results.json)이 정확한 시각·중앙값·p95·응답 크기를 담습니다.

장기 스트레스/인터넷/운영 장비·동시 사용자 성능을 보장하는 수치가 아닙니다. 예약 작업과 장비 부하에 따라 지연이 달라지므로 배포 장비에서 재측정해야 합니다.

### 백업과 남은 운영 확인

실제 Docker 서비스를 잠시 중지해 DB+파일을 일관되게 캡처한 후 재개했습니다. 암호화 파일을 새 DB/별도 파일 볼륨에 복원하고 전체 업무·Auth·Storage·private·로컬 설정의 행 수, RLS, 수납 금액, 사진/PDF 원본 해시를 확인했습니다. 잘못된 비밀번호·변조 파일과 운영 DB를 복구 대상으로 지정하는 요청은 거절했습니다. 현재 DB와 파일은 덮어쓰지 않았습니다.

Windows 작업 스케줄러/DPAPI 등록 스크립트는 Linux에서 실행하지 못했으며 대표 PC에서 설치·첫 실행을 검증해야 합니다. 자동 백업 작업, 외부 백업 복사, 운영 서버/PITR, 직접 DB SELECT 전체 감사, 조회 전용 직원 역할, 외부 메시지 발송은 활성화하지 않았습니다. [운영 체크리스트](deployment-checklist.md)에 남은 확인 사항을 구분했습니다.
